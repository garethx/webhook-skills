# Setting Up Twitch Webhooks

Twitch webhooks are configured **entirely through the API**, not a dashboard.
You register an application, get an app access token, then create an EventSub
subscription that points at your HTTPS callback.

## Prerequisites

- A Twitch account and a registered application in the
  [Twitch Developer Console](https://dev.twitch.tv/console/apps)
- Your application's **Client ID** and **Client Secret**
- A publicly reachable **HTTPS callback on port 443** (use the Hookdeck CLI or a
  tunnel for local development — see below)

## 1. Register an Application

1. Go to the [Twitch Developer Console → Applications](https://dev.twitch.tv/console/apps).
2. Click **Register Your Application**.
3. Set an OAuth redirect URL (e.g. `http://localhost:3000` for development).
4. Copy the **Client ID** and generate a **Client Secret**.

## 2. Get an App Access Token

The webhook transport requires an **app access token** (client credentials
flow). **User tokens are rejected** for webhook subscriptions.

```bash
curl -X POST 'https://id.twitch.tv/oauth2/token' \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -d "client_id=${TWITCH_CLIENT_ID}" \
  -d "client_secret=${TWITCH_CLIENT_SECRET}" \
  -d 'grant_type=client_credentials'
```

The response contains an `access_token`.

## 3. Choose Your Signing Secret

You choose the secret yourself — it is **not** generated by a dashboard. It must
be **10–100 ASCII characters**. Generate a strong random value and store it in
`TWITCH_WEBHOOK_SECRET`; you will need the same value in your handler to verify
signatures.

```bash
# Example: generate a 32-byte hex secret
openssl rand -hex 32
```

## 4. Create a Subscription

Call `POST /helix/eventsub/subscriptions` with the app access token, your
Client ID, the event `type` + `version`, a `condition`, and a `webhook`
transport that includes your callback URL and secret.

```bash
curl -X POST 'https://api.twitch.tv/helix/eventsub/subscriptions' \
  -H "Authorization: Bearer ${APP_ACCESS_TOKEN}" \
  -H "Client-Id: ${TWITCH_CLIENT_ID}" \
  -H 'Content-Type: application/json' \
  -d '{
    "type": "stream.online",
    "version": "1",
    "condition": { "broadcaster_user_id": "1337" },
    "transport": {
      "method": "webhook",
      "callback": "https://your-app.example.com/webhooks/twitch",
      "secret": "'"${TWITCH_WEBHOOK_SECRET}"'"
    }
  }'
```

Notes on specific subscriptions:

- `channel.follow` requires **version `"2"`** and a condition with **both**
  `broadcaster_user_id` and `moderator_user_id`.
- `channel.update` is **version `"2"`**.
- `channel.raid` uses `from_broadcaster_user_id` **or** `to_broadcaster_user_id`
  (not both).

## 5. Handle the Verification Challenge

Immediately after creation, Twitch sends a request with
`Twitch-Eventsub-Message-Type: webhook_callback_verification`. Your handler must
**verify the signature**, then respond **HTTP 200** with the raw `challenge`
string from the body as `text/plain` (not JSON-wrapped). Until you do, the
subscription stays in `webhook_callback_verification_pending` and no
notifications are delivered.

## 6. Confirm the Subscription Is Enabled

```bash
curl 'https://api.twitch.tv/helix/eventsub/subscriptions' \
  -H "Authorization: Bearer ${APP_ACCESS_TOKEN}" \
  -H "Client-Id: ${TWITCH_CLIENT_ID}"
```

A healthy subscription has `"status": "enabled"`.

## Local Development

Twitch requires an HTTPS callback on port 443. For local testing, tunnel to your
machine with the Hookdeck CLI (no account required):

```bash
npx hookdeck-cli listen 3000 twitch --path /webhooks/twitch
```

Use the printed HTTPS URL as the `callback` when creating the subscription.

## Subscription Cost & Limits

Each application has a `max_total_cost` (commonly 10000). User-authorized
subscriptions cost **0**; others count 1 toward the limit. The create-response
returns `total_cost` and `max_total_cost` so you can track usage.
