# Setting Up Synctera Webhooks

Synctera webhooks are configured via the **API** (not a dashboard toggle). There
are two steps: generate a signing secret, then register one or more endpoints.

## Prerequisites

- A Synctera account and API key (sandbox or production)
- Your application's HTTPS webhook endpoint URL (e.g. `https://yourapp.com/webhooks/synctera`)

All API calls use your Synctera API key for authorization (e.g.
`Authorization: Bearer <API_KEY>`). The API key is **only** used to call the
Synctera API — it is **not** the webhook signing secret.

## Step 1: Generate a Signing Secret

The signing secret is generated by Synctera and used to verify webhook
signatures. Create one with an **empty** request body:

```bash
curl -X POST https://api.synctera.com/v0/webhook_secrets \
  -H "Authorization: Bearer $SYNCTERA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{}'
```

The response contains the secret:

```json
{ "secret": "your_signature_secret" }
```

Store this value as `SYNCTERA_WEBHOOK_SECRET`. **This secret — not your API key —
is what you pass to the HMAC verification.**

### Rotating the Secret

Calling `POST /v0/webhook_secrets` again starts a **rolling secret** period. During
rotation, the `Synctera-Signature` header may contain **two** `.`-delimited
signatures (one per active secret). Verify the body against **each** candidate and
accept if any matches — the example handlers already do this.

## Step 2: Register a Webhook Endpoint

Create a webhook with `POST /v0/webhooks`:

```bash
curl -X POST https://api.synctera.com/v0/webhooks \
  -H "Authorization: Bearer $SYNCTERA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://yourapp.com/webhooks/synctera",
    "enabled_events": ["ACCOUNT.UPDATED", "CARD.CREATED", "TRANSACTION.CREATED", "CUSTOMER.*"],
    "is_enabled": true,
    "description": "Primary webhook endpoint",
    "metadata": {}
  }'
```

Fields:

| Field | Description |
|-------|-------------|
| `url` | Your HTTPS endpoint |
| `enabled_events` | Array of event types (supports wildcards like `CUSTOMER.*`) |
| `is_enabled` | `true` to start receiving deliveries |
| `description` | Human-readable label |
| `metadata` | Optional key/value object |

## Step 3: Send a Test Event

Trigger a mock delivery without changing real resources:

```bash
curl -X POST https://api.synctera.com/v0/webhooks/trigger \
  -H "Authorization: Bearer $SYNCTERA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "event_type": "ACCOUNT.UPDATED" }'
```

## Sandbox vs Production

Synctera provides separate sandbox and production environments. Generate a
separate signing secret and register endpoints in each — secrets are not shared
across environments. Use sandbox for local development and testing.

## Delivery Requirements

- Respond **200 within 5 seconds** or the delivery is retried.
- Retries use exponential backoff for up to ~55 hours.
- Events are retained for 60 days.

## Local Testing

Use the Hookdeck CLI to tunnel deliveries to your local machine (no account
required):

```bash
npx hookdeck-cli listen 3000 synctera --path /webhooks/synctera
```

Register the tunnel URL Hookdeck prints as your webhook `url` in Step 2.
