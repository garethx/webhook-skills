# Vercel Log Drains Overview

## What Are Vercel Log Drains?

Log Drains forward logs generated by your Vercel deployments to an external
HTTPS endpoint for storage and analysis. Every time your deployments produce
logs, Vercel POSTs them to your endpoint over HTTPS. To reduce overhead,
**multiple log entries are batched into a single request**.

These are HTTP log-drain deliveries — not traditional "Vercel webhooks", and
**not** [Standard Webhooks](https://www.standardwebhooks.com/). There are no
named event types; instead each log entry carries a `source` and a `level` that
you dispatch on.

Log Drains are available on **Pro and Enterprise** plans and are usage-billed.

## Log Sources (dispatch dimension)

Select which sources to collect in the dashboard under **Additional
configuration for logs**.

| `source` | Emitted when |
|----------|--------------|
| `static` | A request hits a static asset (HTML, CSS, images) |
| `lambda` | A Vercel Function (Node.js API route) runs |
| `edge` | A Vercel Function using the Edge runtime runs |
| `build` | The build step produces output |
| `external` | An external rewrite to a different domain occurs |
| `firewall` | A request is denied by Vercel Firewall rules |
| `redirect` | A request is handled by a redirect rule |

> Note: `redirect` appears in delivered payloads. When choosing sources to
> collect in the dashboard you'll primarily configure `static`, `lambda`,
> `edge`, `build`, `external`, and `firewall`.

## Log Levels

Each entry has a `level`: `info`, `warning`, `error`, or `fatal`.

## Log Environments

Choose which environments send logs to the drain:

| Environment | Details |
|-------------|---------|
| `production` | Logs from production deployments with assigned domain(s) |
| `preview` | Logs from deployments accessed through the generated deployment URL |

## Log Entry Schema

Common fields on each log object (see the full reference for all fields):

| Field | Type | Notes |
|-------|------|-------|
| `id` | string | Unique identifier for the log entry (use for idempotency) |
| `deploymentId` | string | The Vercel deployment ID |
| `source` | enum | `build`, `edge`, `lambda`, `static`, `external`, `firewall`, `redirect` |
| `host` | string | Hostname of the request |
| `timestamp` | number | Unix timestamp (ms) when the log was generated |
| `projectId` | string | The Vercel project ID |
| `level` | enum | `info`, `warning`, `error`, `fatal` |
| `message` | string | Log message (may be truncated if over 256 KB) |
| `buildId` | string | Present on build logs only |
| `path` | string | Function or dynamic path of the request |
| `type` | string | Log output type (`stdout`, `stderr`, `exit`, `middleware`, …) |
| `statusCode` | number | HTTP status; `-1` means the lambda crashed with no response |
| `requestId` | string | Request identifier |
| `environment` | enum | `production` or `preview` |
| `proxy` | object | Proxy request metadata (method, path, clientIp, cache status, WAF action, …) |

## Delivery Formats

A single request contains a batch of log entries in one of two encodings,
configured per drain:

- **JSON** — a JSON array of log objects: `[{…},{…}]`
- **NDJSON** — newline-delimited JSON, one log object per line

Requests may be gzip-compressed if you enable compression on the drain.

## Sampling

Per-drain sampling rules let you control how much log data each drain receives
(by environment and optional path prefix). With no rules, the drain forwards
100% of matching data.

## Reliability

Vercel emails you and flags the drain as **errored** if more than 80% of
deliveries fail, or if there are more than 50 failures in an hour. There is no
documented per-batch retry schedule — treat delivery as at-least-once and make
your handler idempotent using the log entry `id`.
